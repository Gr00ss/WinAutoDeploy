# Win Auto Deploy

Автоматизированное развёртывание Windows 10/11 с помощью Ventoy и Windows Answer File.

Проект собирает установочный носитель, который выполняет большую часть рутинной работы без ручного прохождения мастера Windows: выбирает нужный ISO, размечает системный диск, устанавливает образ, создаёт локального администратора и запускает постустановочный сценарий с программами.

> Важно: Будет производиться чистая установка! Перед запуском установки убедитесь, что на целевом компьютере нет данных, которые нужно сохранить.

## Возможности

- автоматический выбор конфигурации для Windows 11 26H1 или Windows 10 22H2
- русские язык интерфейса, регион и раскладка клавиатур
- автоматическая разметка диска 0 в GPT или MBR в зависимости от режима загрузки
- установка редакции Windows Pro
- создание локальной учётной записи `User` в группе администраторов
- однократный автоматический вход в созданную учётную запись
- запуск дополнительных программ из каталога `Deploy`
- запись журнала основного сценария в `C:\DeployLog.txt`

## Как устроен процесс

1. Компьютер загружается с USB-накопителя Ventoy
2. `ventoy.json` сопоставляет выбранный ISO с шаблоном `autounattend.xml`
3. Windows Setup запускает команды из секции `windowsPE`
4. Скрипт подготовки определяет установочный образ (`install.wim`, `install.esd` или набор `install*.swm`), проверяет answer-файл и определяет тип прошивки
5. Перед изменением диска выполняются проверки диска 0: он должен быть доступен операционной системе как фиксированный жёсткий диск (`Fixed hard disk media`), быть подключён к допустимому контроллеру SATA, SCSI, SAS или NVMe и иметь размер от 70 до 4000 ГиБ
6. Если хотя бы одна проверка не пройдена, Windows Setup останавливается до очистки диска с сообщением `Disk assertion failed`
7. Диск 0 очищается и размечается. В режиме UEFI создаётся GPT-разметка, в режиме Legacy BIOS — MBR-разметка
8. DISM разворачивает Windows Pro на раздел `W:`, а `bcdboot` создаёт загрузчик на разделе `S:`
9. Answer-файл копируется в `C:\Windows\Panther\unattend.xml`, чтобы следующие этапы установки продолжились автоматически
10. После перезагрузки Windows выполняет настройки региона, обхода сетевого требования OOBE, срока действия пароля, SmartScreen, Edge и паузы обновлений
11. При первом входе создаётся временный загрузчик, который ищет подключённый том с `Deploy\MainInstall.ps1`
12. `MainInstall.ps1` запускается с правами администратора и открывает интерактивное меню разделов, где выбираются нужные сценарии установки
13. Answer-файл и временные файлы Wi-Fi удаляются после первого входа

## Структура носителя

### Вариант 1 | только флешка
Можно использовать единый носитель, если вам это позволяет кол-во памяти на флешке.
```text
Ventoy(флешка)/
├── ventoy/
│   ├── autounattend.xml          # Ответы Windows Setup и встроенные этапы настройки
│   └── ventoy.json               # Привязка ISO к answer-файлу Ventoy
├── Deploy/
│   ├── MainInstall.ps1           # Загрузчик постустановочных сценариев
│   ├── RunMainInstall.cmd        # Точка входа с запросом прав администратора
│   ├── 01-Standard/              # Базовое ПО
│   ├── 02-Modular/               # Отдельные модули
│   ├── 03-Software/              # Заготовка: дополнительное ПО
│   ├── 04-Policies/              # Заготовка: системные политики
│   └── Temp/                     # Общие установщики
├── ru-ru_windows_10_22h2.iso     # Образ чистой windows 10 22h2
└── ru-ru_windows_11_26h1.iso     # Образ чистой windows 11 26h2
```

### Вариант 2 | флешка + внешний диск
Так как скрипт ищет папку Deploy по всем носителям, мы можем перенести Deploy на внешний SSD.
```text
Ventoy(флешка)/
├── ventoy/
│   ├── autounattend.xml          # Ответы Windows Setup и встроенные этапы настройки
│   └── ventoy.json               # Привязка ISO к answer-файлу Ventoy
├── ru-ru_windows_10_22h2.iso     # Образ чистой windows 10 22h2
└── ru-ru_windows_11_26h1.iso     # Образ чистой windows 11 26h2

F: (внешний SSD)/
└── Deploy/
    ├── MainInstall.ps1           # Загрузчик постустановочных сценариев
    ├── RunMainInstall.cmd        # Точка входа с запросом прав администратора
    ├── 01-Standard/              # Базовое ПО
    ├── 02-Modular/               # Отдельные модули
    ├── 03-Software/              # Заготовка: дополнительное ПО
    ├── 04-Policies/              # Заготовка: системные политики
    └── Temp/                     # Общие установщики
```

## `ventoy.json`

Конфигурация включает автоматическую установку для двух имён ISO:

| ISO | Шаблон |
| --- | --- |
| `ru-ru_windows_11_26h1.iso` | `autounattend.xml` |
| `ru-ru_windows_10_22h2.iso` | `autounattend.xml` |

В конфигурации шаблон указан как `/ventoy/autounattend.xml`. Поэтому на USB-накопителе файл должен находиться в каталоге `ventoy`, либо путь в JSON нужно изменить под фактическое расположение файла. Имя ISO должно совпадать с записью в конфигурации

## `autounattend.xml`

Это главный файл автоматизации Windows Setup. Он содержит встроенные PowerShell- и CMD-сценарии, которые Windows извлекает в `C:\Windows\Setup\Scripts`

### Этап `windowsPE`

- настраивает русскую раскладку `0419:00000419`
- ищет установочный образ на доступных дисках
- поддерживает `install.wim`, `install.esd` и разделённые `install*.swm`
- подхватывает драйверы из `$WinPEDriver$`, если каталог присутствует
- на UEFI создаёт EFI-раздел 300 МБ, MSR-раздел 16 МБ, раздел Windows и Recovery-раздел
- на Legacy BIOS создаёт системный, Windows и Recovery-разделы
- перед очисткой проверяет, что диск 0 определяется как фиксированный жёсткий диск (`Fixed hard disk media`);
- проверяет подключение диска к допустимому контроллеру SATA, SCSI, SAS или NVMe;
- проверяет размер диска: от 70 до 4000 ГиБ;
- останавливает Windows Setup при провале любой проверки, предотвращая дальнейшие операции с диском;
- полностью очищает диск 0 командой `CLEAN`
- разворачивает образ `Windows 11 Pro` или `Windows 10 Pro`
- создаёт загрузчик командой `bcdboot`
- копирует answer-файл в установленную систему
- задаёт регион устройств как Россию (`GeoID 203`)
- перезагружает компьютер

### Этап `specialize`

Выполняются встроенные `Specialize.ps1` и связанные команды:

- включается `BypassNRO`, чтобы не требовать сетевую учётную запись Microsoft на этапе OOBE
- срок действия пароля локальных пользователей устанавливается без ограничения
- регистрируется задача `PauseWindowsUpdate`, которая при загрузке приостанавливает обновления на 7 дней
- отключаются SmartScreen и связанные уведомления Windows Defender
- скрывается значок Windows Security в области уведомлений
- отключаются первый запуск, Startup Boost и фоновый режим Microsoft Edge

### Этап `oobeSystem` и первый вход

Windows получает русские системные параметры, создаёт пользователя `User` с пустым паролем и добавляет его в локальную группу администраторов. Автоматический вход включён только один раз

При первом входе `FirstLogon.ps1`:

1. сбрасывает счётчик автоматического входа
2. создаёт `DeployLauncher.cmd` в автозагрузке
3. удаляет временные answer-файлы после выполнения

`DeployLauncher.cmd` каждые три секунды проверяет все тома на наличие `Deploy\MainInstall.ps1`. Когда файл найден, запускается PowerShell с `ExecutionPolicy Bypass` и запросом повышения прав UAC. После успешного запуска временный CMD-файл удаляется

## `Deploy/MainInstall.ps1`

`Deploy` в новой версии — это каталог-оркестратор, а не один выполняемый скрипт. `MainInstall.ps1` не содержит фиксированного списка приложений: он читает структуру каталогов и сценариев прямо с носителя и превращает её в интерактивное меню. Каждый каталог первого уровня внутри `Deploy` становится разделом, каждый `.ps1`-файл внутри раздела — отдельным сценарием, который можно запустить по выбору. Каркас рассчитан на запуск с внешнего носителя: все пути строятся относительно `$PSScriptRoot`, поэтому никакой привязки к букве тома нет

### Общая архитектура папок

```text
Deploy/
├── MainInstall.ps1               # Загрузчик: строит меню из файловой системы
├── RunMainInstall.cmd            # Точка входа с запросом прав администратора
├── 01-Standard/
│   ├── Standard.ps1              # Базовый набор ПО + библиотеки VC Redist
│   └── Temp/                     # Собственные установщики раздела
├── 02-Modular/
│   ├── Activation.ps1            # Активация Windows/Office из интернета
│   ├── Defender.ps1              # Запуск WindowsDefenderRemover
│   ├── Drivers.ps1               # Установка драйверов через SDI
│   ├── disable UAC.ps1           # Отключение контроля учётных записей
│   └── Temp/
│       ├── Drivers/              # Дистрибутив SDI (добавляется вручную)
│       └── WindowsDefenderRemover/  # Сторонний инструмент удаления Defender
├── 03-Software/
│   ├── Software.ps1              # Заготовка под дополнительное ПО
│   └── Temp/                     # Собственные ресурсы раздела
├── 04-Policies/
│   ├── Policies.ps1              # Заготовка под системные политики
│   └── Temp/                     # Собственные ресурсы раздела
└── Temp/                         # Общий пул установщиков
    ├── iteron.exe
    ├── AnyDesk.exe
    ├── ChromeSetup.exe
    ├── 7z2602-x64.exe
    ├── PDFXChange/
    │   ├── INSTALL.cmd
    │   └── PDF-XChange.PRO.v10.3.1.387.exe
    └── O365ProPlusRetail.img
```

### Логика каталогов `Temp`

Имя `Temp` для загрузчика — служебное. Любой каталог с таким именем (и на любом уровне вложенности, регистр букв не важен) полностью исключается из меню: он не показывается как раздел и не участвует в обходе структуры. Внутрь можно класть что угодно — установщики, дистрибутивы, драйверы, инструменты третьих сторон. Скрипты обращаются к своим ресурсам напрямую, поэтому `Temp` нужен только как хранилище, а не как часть меню

В проекте два уровня таких каталогов:

- **общий** `Deploy\Temp` — установщики, которые использует раздел `01-Standard`;
- **локальный** `Deploy\<Раздел>\Temp` — ресурсы конкретного раздела, например `Drivers\` и `WindowsDefenderRemover\` внутри `02-Modular`.

Каждый раздел ищет свои файлы относительно `$PSScriptRoot`, то есть рядом с собственным сценарием. `Standard.ps1` проверяет сначала собственный `Temp` (сейчас это `Deploy\01-Standard\Temp`), затем общий `Temp` проекта (`Deploy\Temp`) — поэтому установщики допустимо хранить в любом из этих двух мест

Разделы создаются с собственным каталогом `Temp` уже на стадии сборки носителя. Достаточно положить нужные файлы в `Temp` соответствующего раздела — структура меню от этого не изменится

### Раздел `01-Standard` — базовое ПО

`Standard.ps1` устанавливает рабочий набор программ и дополняет его всеми редакциями Visual C++ Redistributable. Установщики ищутся сначала в `01-Standard\Temp`, затем в `Deploy\Temp`. Каждый необязательный файл проверяется через `Test-Path`: если файла нет, соответствующий шаг пропускается без остановки сценария

| Файл или каталог | Действие |
| --- | --- |
| `iteron.exe` | Копируется на общий рабочий стол и запускается с правами администратора через `AppCompatFlags` |
| `AnyDesk.exe` | Тихо устанавливается как служба, включается запуск с Windows и создаются ярлыки |
| `ChromeSetup.exe` | Устанавливается в тихом режиме |
| `7z2602-x64.exe` | Устанавливается в тихом режиме с ключом `/S` |
| `PDFXChange\INSTALL.cmd` | Запускается через `cmd.exe` из каталога PDF-XChange |
| `O365ProPlusRetail.img` | Монтируется, запускается `Setup.exe`, после завершения образ отключается |
| `winget` (VC Redist) | Последовательно устанавливаются пакеты Visual C++ Redistributable 2005, 2008, 2010, 2012, 2013 и 2015+ в версиях x86 и x64 |

Установка VC Redist выполняется через `winget` и требует соединения с интернетом. После установки ПО скрипт проверяет доступность сети через `77.88.8.8`. При наличии соединения он запускает внешний скрипт активации с `https://get.activated.win` с параметрами `/Ohook /HWID`. При отсутствии соединения активация пропускается

### Раздел `02-Modular` — отдельные модули

Каждый `.ps1`-файл этого раздела — независимый модуль на свою задачу. Модули запускаются по отдельности или выборочно из меню

| Модуль | Задача |
| --- | --- |
| `Drivers.ps1` | Автоматическая установка драйверов через Snappy Driver Installer из `Temp\Drivers`. Находит свежий `SDI_x64_R*.exe`, временно отключает онлайн-обновления SDI, ведёт собственный журнал в `Temp\Drivers\DeploymentLogs` и по ключу `-RestartIfRequired` может перезагрузить систему |
| `Defender.ps1` | Удаляет Windows Defender и связанные компоненты через сторонний инструмент WindowsDefenderRemover из `Temp\WindowsDefenderRemover`. Передаёт свои аргументы в `Script_Run.cmd` |
| `Activation.ps1` | Проверяет доступность интернета и активирует Windows и Office через `get.activated.win` с параметрами `/HWID /Ohook` |
| `disable UAC.ps1` | Отключает контроль учётных записей записью `EnableLUA = 0` в реестре |

Ресурсы модулей лежат в собственном `02-Modular\Temp` и в меню не показываются. `Drivers.ps1` и `disable UAC.ps1` при необходимости сами запрашивают права администратора через UAC и перезапускаются с повышением прав

### Разделы `03-Software` и `04-Policies` — заготовки

`Software.ps1` зарезервирован под установку дополнительных программ, `Policies.ps1` — под применение системных политик. Пока оба сценария являются заглушками, а каталоги первого уровня закреплены в постоянной структуре носителя. Рядом с каждым уже подготовлен собственный `Temp`, чтобы добавление файлов позже не потребовало изменения структуры

### Точка входа и повышение прав

`RunMainInstall.cmd` — основная точка входа на целевом компьютере. Обёртка проверяет, запущена ли она от имени администратора (через `fltmc`), при необходимости перезапускает себя с подтверждением UAC и передаёт управление в `MainInstall.ps1` вместе со всеми переданными аргументами

Подготовка к запуску сценария из каталога `Deploy`:

```powershell
powershell.exe -ExecutionPolicy Bypass -File ".\Deploy\MainInstall.ps1"
```

Корневой `MainInstall.ps1` в корне проекта является совместимым перенаправлением и передаёт параметры в `Deploy/MainInstall.ps1`:

```powershell
powershell.exe -ExecutionPolicy Bypass -File ".\MainInstall.ps1" -Section 01-Standard -Module Standard
```

Такой запуск эквивалентен прямому вызову сценария из каталога `Deploy`

### Архитектура и CLI `MainInstall.ps1`

`Deploy/MainInstall.ps1` является загрузчиком постустановочных сценариев, управляемым структурой каталогов. Скрипт не содержит жёстко заданного списка разделов: он получает структуру меню непосредственно из файловой системы, начиная с каталога, в котором находится сам файл (`$PSScriptRoot`).

#### Правила построения меню

- каждый каталог первого уровня внутри `Deploy` отображается как отдельный раздел;
- вложенные каталоги отображаются как подразделы и могут содержать собственные `.ps1`-сценарии;
- запускаются только файлы с расширением `.ps1`;
- `MainInstall.ps1` не отображается как устанавливаемый модуль;
- каталог `Temp` (любого уровня) и его содержимое не отображаются в меню и не участвуют в поиске разделов;
- имя сценария выводится без расширения `.ps1`;
- сначала отображаются сценарии, затем каталоги, внутри каждой группы используется сортировка по имени;
- перед каждым обновлением интерактивного меню экран терминала очищается;
- запуск выбранного сценария ограничен каталогом `Deploy`.

Рекомендуемая структура разделов:

```text
Deploy/
├── MainInstall.ps1
├── RunMainInstall.cmd
├── 01-Standard/
│   ├── Standard.ps1
│   └── Temp/
├── 02-Modular/
│   ├── Activation.ps1
│   ├── Defender.ps1
│   ├── Drivers.ps1
│   ├── disable UAC.ps1
│   └── Temp/
├── 03-Software/
│   ├── Software.ps1
│   └── Temp/
├── 04-Policies/
│   ├── Policies.ps1
│   └── Temp/
└── Temp/
    └── Временные файлы и установочные ресурсы
```

#### Интерактивный режим

Запуск без параметров открывает меню разделов:

```powershell
powershell.exe -ExecutionPolicy Bypass -File ".\Deploy\MainInstall.ps1"
```

Пример отображения:

```text
=== Win Auto Deploy ===
Root: C:\Deploy
Current: C:\Deploy

[1] 01-Standard /
[2] 02-Modular /
[3] 03-Software /
[4] 04-Policies /
[Q] Quit

Select item: 1
```

После выбора `01-Standard` меню переходит в этот каталог и показывает доступные сценарии:

```text
=== Win Auto Deploy ===
Root: C:\Deploy
Current: C:\Deploy\01-Standard

[1] Standard
[B] Back
[Q] Quit

Select item: 1
Run 'Standard'? [Y/N]
```

`B` возвращает в родительский каталог, `Q` завершает работу. Перед запуском сценария пользователь подтверждает действие клавишей `Y`

#### Параметры командной строки

| Параметр | Назначение | Пример |
| --- | --- | --- |
| без параметров | Открывает интерактивное меню | `./Deploy/MainInstall.ps1` |
| `-List` | Выводит доступные разделы первого уровня | `./Deploy/MainInstall.ps1 -List` |
| `-Section` | Выводит содержимое указанного раздела и завершает работу | `./Deploy/MainInstall.ps1 -Section 01-Standard` |
| `-Module` | Запускает сценарий с указанным именем внутри раздела | `./Deploy/MainInstall.ps1 -Section 01-Standard -Module Standard` |
| `-All` | Последовательно запускает `.ps1`-сценарии первого уровня каждого раздела | `./Deploy/MainInstall.ps1 -All` |
| `-DryRun` | Показывает запуск без фактического выполнения модуля | `./Deploy/MainInstall.ps1 -Section 01-Standard -Module Standard -DryRun` |
| `-NonInteractive` | Запрещает запуск без целевого параметра | `./Deploy/MainInstall.ps1 -NonInteractive -List` |
| `-Help` | Показывает справку по использованию | `./Deploy/MainInstall.ps1 -Help` |

## Журналы и диагностика

При проблемах проверьте:

- `C:\DeployLog.txt` — журнал раздела `01-Standard` (`Standard.ps1`);
- `Deploy\02-Modular\Temp\Drivers\DeploymentLogs\` — журналы установки драйверов через SDI;
- `C:\Windows\Setup\Scripts\Specialize.log` — этап системной настройки
- `C:\Windows\Setup\Scripts\FirstLogon.log` — действия при первом входе
- `%TEMP%\UserOnce.log` — настройка профиля пользователя
- `C:\Windows\Panther\` — журналы Windows Setup

Частая причина пропуска постустановочного этапа — неверная структура носителя: загрузчик ищет именно `Deploy\MainInstall.ps1` на корне одного из доступных томов
