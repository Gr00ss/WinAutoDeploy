# Win Auto Deploy

Автоматизированное развёртывание Windows 10/11 с помощью Ventoy и Windows Answer File.

Проект собирает установочный носитель, который выполняет большую часть рутинной работы без ручного прохождения мастера Windows: выбирает нужный ISO, размечает системный диск, устанавливает образ, создаёт локального администратора и запускает постустановочный сценарий с программами.

> Важно: Будет производиться чистая установка! Перед запуском установки убедитесь, что на целевом компьютере нет данных, которые нужно сохранить.

## Возможности

- автоматический выбор конфигурации для Windows 11 26H1 или Windows 10 22H2
- русские язык интерфейса, регион и раскладка клавиатур
- автоматическая разметка диска 0 в GPT или MBR в зависимости от режима загрузки
- установка редакции Windows Pro
- создание локальной учётной записи `User` в группе администраторов
- однократный автоматический вход в созданную учётную запись
- запуск дополнительных программ из каталога `Deploy`
- запись журнала основного сценария в `C:\DeployLog.txt`

## Как устроен процесс

1. Компьютер загружается с USB-накопителя Ventoy
2. `ventoy.json` сопоставляет выбранный ISO с шаблоном `autounattend.xml`
3. Windows Setup запускает команды из секции `windowsPE`
4. Скрипт подготовки определяет установочный образ (`install.wim`, `install.esd` или набор `install*.swm`), проверяет answer-файл и определяет тип прошивки
5. Перед изменением диска выполняются проверки диска 0: он должен быть доступен операционной системе как фиксированный жёсткий диск (`Fixed hard disk media`), быть подключён к допустимому контроллеру SATA, SCSI, SAS или NVMe и иметь размер от 70 до 4000 ГиБ
6. Если хотя бы одна проверка не пройдена, Windows Setup останавливается до очистки диска с сообщением `Disk assertion failed`
7. Диск 0 очищается и размечается. В режиме UEFI создаётся GPT-разметка, в режиме Legacy BIOS — MBR-разметка
8. DISM разворачивает Windows Pro на раздел `W:`, а `bcdboot` создаёт загрузчик на разделе `S:`
9. Answer-файл копируется в `C:\Windows\Panther\unattend.xml`, чтобы следующие этапы установки продолжились автоматически
10. После перезагрузки Windows выполняет настройки региона, обхода сетевого требования OOBE, срока действия пароля, SmartScreen, Edge и паузы обновлений
11. При первом входе создаётся временный загрузчик, который ищет подключённый том с `Deploy\MainInstall.ps1`
12. `MainInstall.ps1` запускается с правами администратора, устанавливает найденные приложения и пишет журнал
13. Answer-файл и временные файлы Wi-Fi удаляются после первого входа

## Структура носителя

### Вариант 1 | только флешка
Можно использовать единый носитель, если вам это позволяет кол-во памяти на флешке.
```text
Ventoy(флешка)/
├── ventoy/
│   ├── autounattend.xml          # Ответы Windows Setup и встроенные этапы настройки
│   └── ventoy.json               # Привязка ISO к answer-файлу Ventoy
├── Deploy/
│   ├── MainInstall.ps1           # Постустановочная установка приложений
│   └── Инсталлеры приложений
├── ru-ru_windows_10_22h2.iso     # Образ чистой windows 10 22h2
└── ru-ru_windows_11_26h1.iso     # Образ чистой windows 11 26h2
```

### Вариант 2 | флешка + внешний диск
Так как скрипт ищет папку Deploy по всем носителям, мы можем перенести Deploy на внешний SSD.
```text
Ventoy(флешка)/
├── ventoy/
│   ├── autounattend.xml          # Ответы Windows Setup и встроенные этапы настройки
│   └── ventoy.json               # Привязка ISO к answer-файлу Ventoy
├── ru-ru_windows_10_22h2.iso     # Образ чистой windows 10 22h2
└── ru-ru_windows_11_26h1.iso     # Образ чистой windows 11 26h2

F: (внешний SSD)/
└── Deploy/
    ├── MainInstall.ps1           # Постустановочная установка приложений
    └── Инсталлеры приложений  
```

## `ventoy.json`

Конфигурация включает автоматическую установку для двух имён ISO:

| ISO | Шаблон |
| --- | --- |
| `ru-ru_windows_11_26h1.iso` | `autounattend.xml` |
| `ru-ru_windows_10_22h2.iso` | `autounattend.xml` |

В конфигурации шаблон указан как `/ventoy/autounattend.xml`. Поэтому на USB-накопителе файл должен находиться в каталоге `ventoy`, либо путь в JSON нужно изменить под фактическое расположение файла. Имя ISO должно совпадать с записью в конфигурации

## `autounattend.xml`

Это главный файл автоматизации Windows Setup. Он содержит встроенные PowerShell- и CMD-сценарии, которые Windows извлекает в `C:\Windows\Setup\Scripts`

### Этап `windowsPE`

- настраивает русскую раскладку `0419:00000419`
- ищет установочный образ на доступных дисках
- поддерживает `install.wim`, `install.esd` и разделённые `install*.swm`
- подхватывает драйверы из `$WinPEDriver$`, если каталог присутствует
- на UEFI создаёт EFI-раздел 300 МБ, MSR-раздел 16 МБ, раздел Windows и Recovery-раздел
- на Legacy BIOS создаёт системный, Windows и Recovery-разделы
- перед очисткой проверяет, что диск 0 определяется как фиксированный жёсткий диск (`Fixed hard disk media`);
- проверяет подключение диска к допустимому контроллеру SATA, SCSI, SAS или NVMe;
- проверяет размер диска: от 70 до 4000 ГиБ;
- останавливает Windows Setup при провале любой проверки, предотвращая дальнейшие операции с диском;
- полностью очищает диск 0 командой `CLEAN`
- разворачивает образ `Windows 11 Pro` или `Windows 10 Pro`
- создаёт загрузчик командой `bcdboot`
- копирует answer-файл в установленную систему
- задаёт регион устройств как Россию (`GeoID 203`)
- перезагружает компьютер

### Этап `specialize`

Выполняются встроенные `Specialize.ps1` и связанные команды:

- включается `BypassNRO`, чтобы не требовать сетевую учётную запись Microsoft на этапе OOBE
- срок действия пароля локальных пользователей устанавливается без ограничения
- регистрируется задача `PauseWindowsUpdate`, которая при загрузке приостанавливает обновления на 7 дней
- отключаются SmartScreen и связанные уведомления Windows Defender
- скрывается значок Windows Security в области уведомлений
- отключаются первый запуск, Startup Boost и фоновый режим Microsoft Edge

### Этап `oobeSystem` и первый вход

Windows получает русские системные параметры, создаёт пользователя `User` с пустым паролем и добавляет его в локальную группу администраторов. Автоматический вход включён только один раз

При первом входе `FirstLogon.ps1`:

1. сбрасывает счётчик автоматического входа
2. создаёт `DeployLauncher.cmd` в автозагрузке
3. удаляет временные answer-файлы после выполнения

`DeployLauncher.cmd` каждые три секунды проверяет все тома на наличие `Deploy\MainInstall.ps1`. Когда файл найден, запускается PowerShell с `ExecutionPolicy Bypass` и запросом повышения прав UAC. После успешного запуска временный CMD-файл удаляется

## `Deploy/MainInstall.ps1`

Скрипт запускается из каталога `Deploy`, поэтому все установщики ищутся относительно `$PSScriptRoot`. Он создаёт транскрипт журнала `C:\DeployLog.txt` и выполняет шаги последовательно

| Файл или каталог | Действие |
| --- | --- |
| `iteron.exe` | Копируется на общий рабочий стол и запускается с правами администратора через `AppCompatFlags` |
| `AnyDesk.exe` | Тихо устанавливается как служба, включается запуск с Windows и создаются ярлыки |
| `ChromeSetup.exe` | Устанавливается в тихом режиме |
| `7z2602-x64.exe` | Устанавливается в тихом режиме с ключом `/S` |
| `PDFXChange\INSTALL.cmd` | Запускается через `cmd.exe` из каталога PDF-XChange |
| `O365ProPlusRetail.img` | Монтируется, запускается `Setup.exe`, после завершения образ отключается |

Каждый необязательный файл проверяется через `Test-Path`. Если файла нет, соответствующий шаг пропускается без остановки сценария.Установщики нужно добавить на подготовленный носитель самостоятельно

В конце скрипт проверяет доступность интернета через `77.88.8.8`. При наличии соединения он загружает и запускает внешний скрипт активации с `https://get.activated.win` с параметрами `/Ohook /HWID`. При отсутствии соединения активация пропускается

### Требуемое содержимое `Deploy`

```text
Deploy/
├── MainInstall.ps1
├── iteron.exe                 
├── AnyDesk.exe                
├── ChromeSetup.exe            
├── 7z2602-x64.exe             
├── PDFXChange/
│   └── INSTALL.cmd             
└── O365ProPlusRetail.img      
```

## Подготовка и запуск

1. Скачайте последнюю версию Ventoy с официальной страницы загрузки: [Прямая ссылка](https://sourceforge.net/projects/ventoy/files/).

2. Скачайте последний релиз этого проекта: [Последний релиз](https://github.com/Gr00ss/WinAutoDeploy/releases/latest). Так же скачайте отдельно архив Deploy с прикреплённого google drive. Так же рядом будут лежать готовые чистые образы

3. Разархивируйте скачанный архив и запустите `Ventoy2Disk.exe`. Выберите нужную флешку и установите Ventoy. Все данные на выбранной флешке будут удалены

4. Выберите подходящий вариант размещения файлов:

    <details>
    <summary>Вариант 1 (только флешка)</summary>

    На флешку перенесите готовые образы. Затем в корне создайте папку **ventoy** и перенесите в неё файлы `autounattend.xml` и `ventoy.json`. После этого перенесите в корень флешки папку **Deploy**
    *[Обратите внимание на структуру носителя](#структура-носителя)*

    </details>

    <details>
    <summary>Вариант 2 (флешка + SSD)</summary>

    На флешку перенесите готовые образы. Затем в корне создайте папку **ventoy** и перенесите в неё файлы `autounattend.xml` и `ventoy.json`. В корень внешнего SSD перенесите папку **Deploy**
    *[Обратите внимание на структуру носителя](#структура-носителя)*

    </details>

    

5. Проверьте имена ISO-образов Windows. Они должны в точности совпадать с именами, указанными в файле `ventoy/ventoy.json`

## Журналы и диагностика

При проблемах проверьте:

- `C:\DeployLog.txt` — журнал `MainInstall.ps1`;
- `C:\Windows\Setup\Scripts\Specialize.log` — этап системной настройки
- `C:\Windows\Setup\Scripts\FirstLogon.log` — действия при первом входе
- `%TEMP%\UserOnce.log` — настройка профиля пользователя
- `C:\Windows\Panther\` — журналы Windows Setup

Частая причина пропуска постустановочного этапа — неверная структура носителя: загрузчик ищет именно `Deploy\MainInstall.ps1` на корне одного из доступных томов
